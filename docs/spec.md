# CallTimeWidget 仕様書

パッケージ名:io.github.eightbrows.CallTimeChecker

通話時間・通話料金積算ウィジェット

| 項目 | 内容 |
|---|---|
| ドキュメント版数 | 0.1 |
| 作成日 | 2026-08-18 |
| 状態 | 検討中 |

---

## 1. 概要

契約中の音声通話プランについて、当月の積算通話時間と概算通話料金をホーム画面ウィジェットに常時表示する Android アプリケーション。

端末の通話履歴 (`CallLog`) を定期的に取得してローカル DB に蓄積し、契約プランの設定値に基づいて集計・課金計算を行う。

### 1.1 解決したい課題

- 定額枠（月間 70 分等）をどれだけ消費したかがキャリアアプリを開かないと分からない
- キャリアアプリは起動が重く、反映も遅い
- ホーム画面で残量を一目で把握したい

### 1.2 設計方針

| 方針 | 理由 |
|---|---|
| 生ログをそのまま保存し、判定・課金計算は集計時に実施 | 設定変更時に過去分も再計算され、キャリア明細と突き合わせて設定を追い込める |
| 集計ロジックを純粋関数として分離 | 実機なしで JVM ローカルテストが可能 |
| 表示は常にローカル DB を参照 | 端末の `CallLog` が削除されても影響を受けない |
| プラン形式を 2 パラメータに抽象化 | 3 種のプラン形式を分岐なしで扱える |
| 外部ライブラリ・ネットワーク通信なし | 権限の追加要求が不要、保守が容易 |

## 2. スコープ

### 2.1 対象

- 標準の電話アプリによる音声発信の積算
- 契約起算日に基づく期間集計
- 定額枠消費量および超過料金の算出
- ウィジェットへの表示（30 分自動更新・タップ手動更新）

### 2.2 対象外

- 着信通話の積算（日本の一般的なプランでは課金対象外のため）
- IP 電話 / VoIP アプリ（Google Meet 等）の通話。`CallLog` に記録されないため原理的に取得不可
- データ通信量の集計
- キャリアの請求システムとの連携・照合
- 複数 SIM の個別集計（シングル SIM 運用前提）
- Google Play への公開（`READ_CALL_LOG` は Play 側で用途審査対象。GitHub Releases での自己配布を想定）

## 5. 機能要件

### 5.1 通話記録の取得

#### 5.1.1 取得元

`android.provider.CallLog.Calls` コンテンツプロバイダ。

| 列 | 用途 |
|---|---|
| `DATE` | 通話開始時刻（epoch millis）。主キーとして使用 |
| `DURATION` | 通話接続時間（秒）。未応答は 0 |
| `NUMBER` | 相手先番号。除外判定に使用 |
| `TYPE` | 通話種別。`OUTGOING_TYPE`(2) のみ対象 |
| `PHONE_ACCOUNT_ID` | 発信元アカウント。IP 電話混入時の切り分け用 |

#### 5.1.2 同期処理

```
1. last = SELECT MAX(date_millis) FROM call_record   (レコードなしの場合は 0)
2. CallLog を以下の条件で問い合わせ
     TYPE = 2 AND DATE >= (last - 86400000)
   ※ 24 時間分の重複読み込みにより、ログ書き込み順序の揺らぎを吸収する
3. 取得したレコードを INSERT OR IGNORE で投入
```

主キー重複により冪等性が担保される。差分のみ対象とするため 30 分間隔での実行でも負荷は無視できる。初回のみ `CallLog` 全件を読み込む。

#### 5.1.3 実行タイミング

| 契機 | 備考 |
|---|---|
| ウィジェット自動更新（30 分周期） | `updatePeriodMillis` による |
| ウィジェットタップ | 手動更新 |
| アプリ本体の起動時 | |
| 設定変更後 | 同期は不要だが再集計・再描画を行う |

### 5.2 集計期間の決定

起算日 `startDay`（1〜31）に対し、集計期間は `[開始日 00:00:00.000, 翌月開始日 00:00:00.000)` の半開区間とする。タイムゾーンは端末のデフォルトを使用する。

```kotlin
/** 指定月における期間開始日。存在しない日は月末にクランプする */
fun periodStartDate(startDay: Int, ym: YearMonth): LocalDate =
    ym.atDay(minOf(startDay, ym.lengthOfMonth()))

/** today が属する集計期間の「開始月」 */
fun periodMonth(startDay: Int, today: LocalDate): YearMonth {
    val ym = YearMonth.from(today)
    return if (!today.isBefore(periodStartDate(startDay, ym))) ym else ym.minusMonths(1)
}

/** 開始月を指定した集計期間 */
fun periodOf(startDay: Int, zone: ZoneId, month: YearMonth): Pair<Long, Long> {
    val start = periodStartDate(startDay, month)
    val end = periodStartDate(startDay, month.plusMonths(1))
    return start.atStartOfDay(zone).toInstant().toEpochMilli() to
           end.atStartOfDay(zone).toInstant().toEpochMilli()
}

fun currentPeriod(startDay: Int, zone: ZoneId, today: LocalDate): Pair<Long, Long> =
    periodOf(startDay, zone, periodMonth(startDay, today))
```

集計期間は開始月（`YearMonth`）と 1 対 1 に対応するため、月送り（5.6）は開始月を `YearMonth` 単位でずらして表す。基準日を `LocalDate.plusMonths()` でずらす方式は採らない（`LocalDate` の日クランプと `periodStartDate()` の月末クランプが二重にかかり、起算日 31・基準日 3/30 のようなケースで前月が今月と同じ期間になるため）。

#### 5.2.1 仕様上の決定事項

| 論点 | 決定 |
|---|---|
| 起算日 25 の場合の範囲 | 25 日 00:00 〜 翌月 24 日 23:59:59.999 |
| 起算日 31、2 月の扱い | 2 月 28 日（閏年は 29 日）にクランプ |
| 期間をまたぐ通話 | 通話**開始時刻**が属する期間に計上する |
| 設定可能範囲 | 1〜31 |

### 5.3 除外判定

#### 5.3.1 判定手順

1. 番号文字列からハイフン、スペース、括弧を除去する
2. 除外リストの各エントリと前方一致比較を行う
3. いずれかに一致した場合、その通話は定額枠を消費せず、課金計算の対象外とする
4. 除外された通話は「除外通話時間」として別枠で集計・表示する

番号が空文字列または `null`（非通知等）の場合は除外扱いとしない。

#### 5.3.2 除外リスト初期値

| プレフィックス | 内容 |
|---|---|
| `0570` | ナビダイヤル |
| `0180` | テレドーム |
| `0990` | ダイヤルQ2 |
| `0120` | フリーダイヤル |
| `104` | 番号案内 |
| `110` | 警察 |
| `118` | 海上保安庁 |
| `119` | 消防・救急 |
| `188` | 消費者ホットライン |
| `+` | 国際発信 |

設定画面で編集可能とする（改行区切りのテキストとして保持）。

### 5.4 料金計算

#### 5.4.1 パラメータ

| 変数 | 意味 | 単位 |
|---|---|---|
| `monthlyFreeSec` | 月間定額枠 | 秒 |
| `perCallFreeSec` | 1 通話あたり無料時間 | 秒 |
| `unitSec` | 課金単位 | 秒（30 または 60） |
| `unitPrice` | 単位あたり金額 | 円 |

#### 5.4.2 プラン形式との対応

| プラン形式 | `monthlyFreeSec` | `perCallFreeSec` | 例 |
|---|---|---|---|
| 月間定額型 | 定額枠の秒数（1 分以上） | 0 | 月 70 分 + 22 円/30 秒 |
| 1 通話定額型 | 0 | 無料時間の秒数（1 分以上） | 5 分かけ放題 + 22 円/30 秒 |
| 従量課金 | 0 | 0 | 22 円/30 秒 |

3 択のいずれも「一方だけが正」または「両方 0」で、プラン形式と 2 フィールドは 1 対 1 に対応する。保存値からプラン形式を一意に導出でき（`derivePlanType()`）、読み込み時はこの導出結果を採用する（5.7）。

`calculate()` は両方が正の値でも動作するが、設定画面から作れないためプラン形式としては用意しない。

#### 5.4.3 アルゴリズム

```kotlin
data class Settings(
    val monthlyFreeSec: Int,
    val perCallFreeSec: Int,
    val unitSec: Int,
    val unitPrice: Int,
    val excludePrefixes: List<String>
)

data class Result(
    val countedSec: Int,       // 定額対象として計上した通話の実時間合計
    val quotaConsumedSec: Int, // 実際の定額枠消費量（通話ごとに単位切り上げした値の合計）
    val billedSec: Int,        // 課金対象秒数（単位切り上げ済み）
    val amount: Int,           // 概算料金（円）
    val excludedSec: Int,      // 除外番号への通話の実時間合計
    val callCount: Int,        // 対象通話件数
    val billedCallCount: Int   // 課金が発生した通話件数
)

fun calculate(records: List<CallRecord>, s: Settings): Result {
    var pool = s.monthlyFreeSec
    var countedSec = 0
    var quotaConsumedSec = 0
    var billedSec = 0
    var excludedSec = 0
    var callCount = 0
    var billedCallCount = 0

    for (r in records.sortedBy { it.dateMillis }) {
        if (isExcluded(r.number, s.excludePrefixes)) {
            excludedSec += r.durationSec
            continue
        }
        if (r.durationSec == 0) continue   // 未応答

        countedSec += r.durationSec
        callCount++

        val over = maxOf(0, r.durationSec - s.perCallFreeSec)
        if (over == 0) continue

        // 通話ごとに課金単位へ切り上げる
        val units = ceilDiv(over, s.unitSec) * s.unitSec
        // 枠が尽きた後も、消費量そのものは切り上げ値の合計として積み上げる
        quotaConsumedSec += units
        val consumed = minOf(units, pool)
        pool -= consumed
        val billed = units - consumed
        if (billed > 0) {
            billedSec += billed
            billedCallCount++
        }
    }
    return Result(
        countedSec = countedSec,
        quotaConsumedSec = quotaConsumedSec,
        billedSec = billedSec,
        amount = billedSec / s.unitSec * s.unitPrice,
        excludedSec = excludedSec,
        callCount = callCount,
        billedCallCount = billedCallCount
    )
}

fun ceilDiv(a: Int, b: Int): Int = (a + b - 1) / b
```

`countedSec` と `quotaConsumedSec` は用途が異なる。

| フィールド | 意味 | 主な用途 |
|---|---|---|
| `countedSec` | 通話の実時間合計（切り上げなし） | 実際に何分話したかの参考表示（「履歴集計」の実時間表示のみ） |
| `quotaConsumedSec` | 通話ごとに課金単位へ切り上げた値の合計 | 全プランの「通話時間」表示（5.5.1 / 5.6.1）・定額枠の配色判定 |

短い通話が多いほど両者は乖離する（2 秒の通話 39 件は `countedSec = 78` 秒、30 秒単位で `quotaConsumedSec = 1170` 秒）。「通話時間」表示に `quotaConsumedSec` を使うのは、定額枠を実際に減らすのも料金の根拠（`quotaConsumedSec ÷ unitSec × unitPrice`）になるのも後者のため。

#### 5.4.4 計算上の決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 切り上げの単位 | 通話ごとに切り上げ | キャリアの課金方式に最も近い |
| 定額枠の消費量 | 切り上げ**後**の秒数（`quotaConsumedSec`） | 同上 |
| 枠が尽きた後の消費量 | 切り上げ値の合計を積み上げ続ける | 枠に対して何分超過したかを表示するため |
| 通話の処理順 | 通話開始時刻の昇順 | 定額枠の消費順序を実際の時系列に一致させる |
| 通話時間 0 秒 | 集計対象外 | 未応答・不通のため |
| 除外番号への通話 | 定額枠を消費せず、料金も計上しない | 別建て課金のため本アプリでは追跡しない |

### 5.5 ウィジェット

#### 5.5.1 表示内容

1x1 を初期配置とし、縦に 1x2 まで広げられる（5.5.5）。上段 3 : 下段 2 で分割し、間に区切り線。上段は通話時間（月間定額型はさらに無料枠）、下段は通話金額。数字はアプリ本体「現在の状況」（5.6.1）と同じ値を使う。1 項目はラベル（小）+ 数字・単位（大+小）の 2 行構成。

| プラン形式 | 上段の項目 |
|---|---|
| 月間定額型 | 通話時間（`quotaConsumedSec`）+ 無料枠（残り） |
| 1 通話定額型 / 従量課金 | 通話時間（`quotaConsumedSec`）のみ |

無料枠が無いプランはその行を `GONE` にする。下段は全プラン共通で通話金額（`Result.amount`、3 桁区切り）。通話時間は全プランとも `quotaConsumedSec` で統一し、金額の計算根拠と一致させる（5.4.3）。超過の有無は文字ではなく背景色（5.5.3）だけで表す。件数はウィジェットには出さない。

**自動更新の印**: 自動更新（`onUpdate`）経由の再描画のときだけ、「通話金額」のラベルに `⌚`（U+231A）を添える。手動更新・設定変更では付けない。

**文字サイズ**: `autoSizeTextType` で表示領域に合わせて自動調整する。ラベル・数字・単位は 1 つの `TextView` にまとめ、大きさの差は `RelativeSizeSpan` / `StyleSpan` で付ける（分けるとリサイズ時に比率が崩れるため）。桁数の違いで同じ項目でも大きさが揃わないため、基準文字列（通話時間=`00.0`、通話金額=`000`）に満たない桁は透明な「0」で埋めて幅をそろえる（奇数差は半分サイズの桁を両側に配置し中心をずらさない）。

実装上の制約: autoSize は幅・高さの両方が確定した `TextView` でしか働かない。区切り線は `ImageView` を使う（`RemoteViews` は素の `View` をインフレートできないため）。

#### 5.5.2 表示状態

| 状態 | 表示 | 遷移先 |
|---|---|---|
| `NORMAL` | 上記の通常表示 | タップで手動更新 |
| `NO_PERMISSION` | 「タップして権限を許可」 | タップでアプリ本体を起動 |
| `ERROR` | 「更新失敗」 | タップで再試行 |

#### 5.5.3 配色

| 条件 | 色 |
|---|---|
| 残り時間が警告しきい値より多い | 通常色 |
| 残り時間が警告しきい値以下、かつ枠消費量が定額枠未満 | 警告色 |
| 枠消費量が定額枠以上 | 超過色 |

残り時間は `定額枠 − Result.quotaConsumedSec`。警告しきい値は設定項目（5.7、初期値は定額枠の 20%）、超過色の境界は定額枠そのもの。1 通話定額型・従量課金には定額枠が無いため、1 通話定額型は課金額の有無で通常色／警告色を切り替え（超過色は使わない）、従量課金は常に通常色。

背景は透過率（5.7）を反映した ARGB を実行時に設定する（色の実体はパレット、5.7）。文字色は背景の輝度から自動選択し、コントラスト比 4.5 以上を確保する（`widgetTextColorOn()`）。

#### 5.5.4 更新

| 項目 | 内容 |
|---|---|
| 自動更新 | `appwidget-provider` の `updatePeriodMillis="1800000"`（30 分。システムの最小値） |
| 手動更新 | ウィジェットタップ → `PendingIntent.getBroadcast`（API 31 以降は `FLAG_IMMUTABLE` 必須）→ 自身の `onReceive` でカスタムアクションを処理 |
| 処理内容 | 同期 → 再集計 → `AppWidgetManager.updateAppWidget` |
| スレッド | `onUpdate` / `onReceive` はメインスレッドかつ 10 秒制限のため、`goAsync()` + Executor でバックグラウンド実行する |
| 再起動時 | `updatePeriodMillis` はシステムが再スケジュールするため `BOOT_COMPLETED` の受信は不要 |

自動更新（`onUpdate`）、手動更新・設定変更（`onReceive` のカスタムアクション）は別経路のため、どちらで描いたかは描画時に判別できる。自動更新の経路だけ「通話金額」に `⌚` を付ける（5.5.1）。Doze 中は自動更新が遅延するが用途上許容する。

#### 5.5.5 対応サイズ

1x1 を初期配置（`targetCellWidth` / `targetCellHeight` とも 1）とし、`resizeMode="vertical"` で 1x2 まで縦に広げられる（横方向は対象外）。

リサイズの下限・上限は `minResizeHeight` / `maxResizeHeight`（API 31 以降）で指定する。セル 1 つの実寸はランチャーごとに異なるため、指定した値によっては 1x2 より広い／狭い範囲までリサイズできる場合がある。上限を低く指定しすぎるとリサイズハンドル自体が出なくなる点に注意（実機で確認しながら調整する）。

### 5.6 アプリ本体

単一 Activity 構成。メイン画面は「サマリ」「通話履歴」の 2 タブ（`TabRow` + `HorizontalPager`）で構成する。

| 領域 | 内容 |
|---|---|
| ヘッダ | アプリ名「通話時間確認アプリ」と、手動更新・設定のボタン。タブの外に置く |
| 月送り | 横 1 行。左に相対ラベル（今月 / 1ヶ月前…）、右に「← 前月」「次月 →」。ヘッダとタブの間、タブの外に置く |
| サマリタブ | 上段（プラン情報）+ 中段「現在の状況」。5.6.1 |
| 通話履歴タブ | 「履歴集計」+ 通話履歴（内訳リスト）。5.6.2 |
| 権限 | 未許可時に要求ボタンを表示 |

ヘッダ・月送りをタブの外に置くのは、どちらのタブからも同じ位置で操作でき、内訳リストと一緒にスクロールしないようにするため。

**ボタン**: ヘッダの更新・設定、月送りの前月・次月はいずれも `FilledTonalButton`、48dp 高・水平パディング 16dp・`titleMedium`（押しやすさと、押せることの視認性のため）。

**月送りの配置**: 相対ラベルは行の左（`weight(1f)`）、ボタン 2 つは右端に 8dp 間隔で隣接配置（続けて押す際の移動量を減らすため）。上 12dp・下 16dp の余白で誤タップを防ぐ。

**月送りの仕様**: 選択中の月は `monthOffset`（0 = 今月）として画面の状態のみで保持し、アプリを開き直すと今月に戻る。過去方向の制限は無い。「次月」は `monthOffset = 0` で無効化する。ラベルは相対表記（起算日次第で絶対月表記の解釈が割れるため）。設定は過去の月を選んでいても常に現在の値を使い、変更履歴は保持しない。通話履歴タブの内訳リストも同じ期間で絞り込む。ウィジェットは常に今月を表示する。

**タブ**: タップに加え左右スワイプでも切り替える（`PagerState` を `TabRow` と共有、インジケーターはスワイプに追従して補間）。縦スクロール（内訳リスト）と横スワイプの振り分けは Compose の入れ子スクロールに任せる。リスト上での縦優勢ドラッグはスクロール、ほぼ水平なドラッグやリスト外（履歴集計・フィルタ行など）から始まるドラッグはタブ切り替えとなる。

#### 5.6.1 サマリタブ

| 段 | 内容 |
|---|---|
| 上段 | `プラン: 月間定額型`、`期間: 2026/08/01 - 2026/08/31`、`無料枠: 70分`（月間定額型のみ）または `1通話無料枠: 5分`（1 通話定額型のみ）、`単価: 22円 / 30秒`（全プラン共通） |
| 中段 | 見出し「現在の状況」。項目ごとにラベル行（小）と値行（大）をペアで縦に並べる |
| 下段 | 見出し「履歴集計」。通話履歴タブ（5.6.2）と同じ内容を再掲（同じ composable を両方から呼ぶ） |

中段の項目：

| プラン形式 | ラベル | 値 | バッジ |
|---|---|---|---|
| 月間定額型 | `通話時間 / 無料枠残` | `20.5 / 49.5分` | `quotaConsumedSec > monthlyFreeSec` なら `超過あり`、そうでなければ `超過なし` |
| 1 通話定額型 | `通話時間` | `128.0分` | `billedCallCount > 0` なら `超過あり`、そうでなければ `超過なし` |
| 従量課金 | `通話時間` | `42.0分` | なし |
| 全プラン共通 | `通話金額` | `1,220円` | なし |

通話時間は全プラン `Result.quotaConsumedSec` を基準とし、ウィジェット（5.5.1）と数字を一致させる。月間定額型以外は `quotaConsumedSec` と `billedSec` が常に一致する。実際の通話時間は「履歴集計」に「通話時間（実時間）」（`countedSec`）として併記する。分表示は小数第一位（`formatMinutes()`）、金額は 3 桁区切り（`formatAmount()`）でウィジェットと共用。「履歴集計」の実時間・除外時間は分秒表示とする。表示分岐は値ではなく `PlanType` で行う。

#### 5.6.2 通話履歴タブ

| 領域 | 内容 |
|---|---|
| 履歴集計 | `通話件数: 41件（課金対象 5件）`、`通話時間（実時間）: 1分35秒`、`通話時間（除外）: 0分0秒` |
| 通話履歴 | 期間内の通話一覧。日時、番号、通話時間、判定結果（定額内 / 課金 ¥XX / 除外 / 未応答）、課金枠の秒数。「全件 / 課金対象のみ」の表示フィルタ切り替え可 |

内訳リストはキャリアの請求明細と突き合わせる唯一の手段のため、通話履歴タブの残り領域をすべて割り当てる。各行の判定結果は `CallDetail.billedSec` 基準（実際に料金が発生したか）とし、枠を消費した通話には `CallDetail.quotaConsumedSec` を `定額内・課金枠 30秒` の形式で併記する。「全件 / 課金対象のみ」フィルタは表示上の絞り込みのみで `calculate()` / `calculateDetails()` には影響しない（`billedSec > 0` で判定）。

### 5.7 設定項目

| 項目 | 型 | 範囲 | 初期値 | 備考 |
|---|---|---|---|---|
| プラン形式 | 選択 | — | 月間定額型 | 月間定額型 / 1 通話定額型 / 従量課金 |
| 起算日 | 分 | 1〜31 | 1 | 契約開始日 |
| 定額枠 | 分 | 1〜1440 | 70 | 入力できるのは月間定額型のときのみ。それ以外は 0 固定 |
| 通話別無料時間 | 分 | 1〜180 | 5 | 入力できるのは 1 通話定額型のときのみ。それ以外は 0 固定 |
| 課金単位 | 30 / 60 | — | 30 | 秒 |
| 単位金額 | 円 | 0〜999 | 22 | |
| 除外番号リスト | テキスト | — | 5.3.2 の初期値 | 改行区切り |
| 警告しきい値（残り分） | 分 | 1〜(定額枠 − 1) | 定額枠の 20%（初期値では 14） | 残りがこの分数以下で警告色。入力できるのは月間定額型のときのみ（5.5.3） |
| ウィジェット背景の透過率 | 段階 | 0〜8 | 0（不透明） | 0%〜100% を 12.5% 刻みの 9 段階（5.5.3） |
| ウィジェット背景色（通常色 / 警告色 / 超過色） | 添字 | 0〜7 | ホワイト / オレンジ / レッド | 8 色のプリセットパレットから選ぶ（5.5.3） |
| アプリの配色 | 選択 | — | システムに従う | システムに従う / ライト / ダーク。アプリ本体の画面のみに効く |

保存先は `SharedPreferences`。

**入力検証**: 範囲外・空欄の欄はエラー表示のうえ保存ボタンを無効化する（自動クランプはしない）。0 固定側の欄は検証対象外。定額枠・通話別無料時間の下限が 1 なのは、0 だと従量課金と区別が付かなくなるため。プラン形式切替で 0 固定だった欄が有効になり値が 0 のままなら初期値（70 分 / 5 分）を自動投入する。

**マイグレーション**: 読み込み時は保存済み `plan_type` を信用せず、定額枠・通話別無料時間の実値から `derivePlanType()` で導出し直す。プラン形式は内部的には `monthlyFreeSec` / `perCallFreeSec` の 2 フィールドのみで、集計ロジックはプラン形式自体を参照しない。現在のプラン形式はラジオボタンとサマリの集計期間行（5.6）に表示する。

**警告しきい値（残り分）**: 「残り何分か」で保持する（定額枠を変えても意味が変わらないため）。上限は定額枠 − 1。定額枠をしきい値以下に変更した場合はエラー表示とし自動クランプしない（例外はマイグレーション時と月間定額型への切替時のみ、既定値 20% を再投入）。UI は定額枠と同じ数値欄 + ±1 分ボタン。

**ウィジェット背景色**: 通常色 / 警告色 / 超過色それぞれ 8 色のプリセットパレットから選ぶ（任意色にすると読めない配色を作れてしまうため）。保存はパレット添字。UI は現在の 3 色を矢印でつないで 1 行表示し、タップでパレットダイアログを開く。透過率は 3 色共通。

**ウィジェット背景の透過率**: 0〜8 の段階インデックスで保持する（12.5% 刻み）。UI はプルダウンで、配置は背景色設定の下（先に色→透け具合の順）。

**アプリの配色**: システムに従う / ライト / ダークの 3 択で、アプリ本体の画面にのみ効く（ウィジェットの背景色とは独立）。保存値は enum 名ではなく固定文字列とする（R8 の難読化で enum 名が変わりうるため、11.1）。

**除外番号リスト・権限・バージョン情報**: 除外番号リストは折りたたみ式（閉時は件数と先頭数件のプレビューのみ）。`READ_CALL_LOG` の許可状態（8 章）もここに表示し、未許可ならその場で要求、許可済みでも OS のアプリ権限設定への導線を残す。

バージョン情報は `項目名: 値` の並びで表示する。

| 項目 | 値 | 動作 |
|---|---|---|
| バージョン | `BuildConfig.VERSION_NAME` | — |
| ライセンス | `Apache License 2.0` | タップでリポジトリの `LICENSE` をブラウザで開く |
| 公式サイト | `eightbrows.github.io` | タップで公式サイトをブラウザで開く |

**画面構成**: 見出し「設定」と「キャンセル」「保存」ボタンは画面上部に固定し、入力項目のスクロール領域とは分ける。プラン形式は横 1 行ラジオ、数値入力は 2 カラム。0 固定の欄も隠さずグレーアウトのまま残す（プラン切替時にレイアウトが動かないように）。

## 6. データ設計

### 6.1 テーブル定義

```sql
CREATE TABLE call_record (
  date_millis  INTEGER NOT NULL PRIMARY KEY,  -- 通話開始時刻
  duration_sec INTEGER NOT NULL,              -- 接続時間（秒）
  number       TEXT,                          -- 相手先番号
  type         INTEGER NOT NULL,              -- CallLog.Calls.TYPE
  account_id   TEXT                           -- PHONE_ACCOUNT_ID
);

CREATE INDEX idx_call_record_date ON call_record(date_millis);
```

### 6.2 設計上の決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 主キー | `date_millis` | `CallLog._ID` は端末側でログが削除・再構築されると再利用される可能性があるため使用しない。通話開始時刻はミリ秒精度で実質的に一意 |
| 保存内容 | 生ログのみ | 除外判定・課金計算の結果は保存しない。設定変更時に過去分を含めて再計算するため |
| 保持期間 | 無期限 | 年間数千件程度であり容量上の問題がない |
| 削除 | 行わない | 過去期間の参照および設定検証のため |
| `account_id` | 保持する | IP 電話の混入が判明した場合の切り分けに使用 |

| `android.permission.READ_CALL_LOG` | dangerous | 通話履歴の取得 |

## 9. 制約・既知の限界

| 項目 | 内容 | 対応 |
|---|---|---|
| 通話中の反映 | `CallLog` は通話終了後に書き込まれるため、通話中は積算に反映されない | 仕様として許容 |
| IP 電話 | Google Meet 等は `CallLog` に記録されないため取得不可 | 積算不要のため問題なし。混入が判明した場合は `account_id` で切り分け、除外ルールを追加 |
| `CallLog` の保持上限 | 機種により保持件数に上限がある（500 件程度の例あり） | ローカル DB への蓄積により回避 |
| 初回導入時 | 導入以前の通話は `CallLog` に残っている分しか取得できない | 期間途中での導入時は数値が不完全になる旨をアプリ内に表示 |
| 課金計算の精度 | 切り上げ単位・カウント開始タイミングがキャリアにより異なる | 内訳リストで明細と突き合わせ、設定で調整 |
| Doze による遅延 | 自動更新が最大で数十分遅延する場合がある | 手動更新で補完。必要ならバッテリー最適化の除外を案内 |
| 表示金額の位置づけ | あくまで概算。基本料金・ユニバーサルサービス料・消費税等は含まない | アプリ内に注記 |

### 10.1 ユニットテスト（JVM ローカル）

集計ロジックは `List<CallRecord>` と `Settings` を受けて `Result` を返す純粋関数であり、実機なしで検証可能。以下を優先的にテストする。

| 対象 | ケース |
|---|---|
| 期間算出 | 起算日 1 / 25 / 31、2 月（閏年・平年）、月初日・月末日の境界 |
| 月送り | 開始月の判定、開始月指定での期間算出（起算日 25 / 31、閏年）、月末クランプされる月の前月が今月と別期間になること |
| 警告しきい値 | 既定値（定額枠の 20%）、範囲（1〜定額枠 − 1）、範囲が空になる定額枠 1 分、マイグレーションでの復旧 |
| ウィジェット表示 | ラベル・数字・単位を分けて返すこと、月間定額型が 2 項目になること、無料枠が無いプラン形式で項目が落ちること、金額の 3 桁区切り |
| ウィジェットの文字サイズ | 各プランが同じ基準文字列を持つこと、基準文字列と実際の値の桁数の関係 |

| アプリの配色 | 初期値が「システムに従う」、保存値が enum 名と独立していること、未保存・未知の値が既定に倒れること |
| ウィジェット配色 | 警告色の切り替わり境界、超過色が定額枠固定であること、パレット添字と色の対応、文字色のコントラスト比 4.5 以上 |
| 切り上げ | 端数 0 秒、1 秒、29 秒、30 秒、31 秒（`unitSec` = 30 / 60 の両方） |
| 定額枠 | 枠未使用、枠内、枠ちょうど、枠をまたぐ 1 通話、枠超過 |
| 通話別無料時間 | 無料時間ちょうど、1 秒超過、大幅超過 |

### 10.2 実機確認

| 項目 | 確認内容 |
|---|---|
| 同期の冪等性 | 複数回更新しても件数・積算値が変化しないこと |
| 自動更新 | 30 分周期で更新されること（Doze 下での遅延幅も確認） |
| 権限フロー | 未許可 → ウィジェット表示 → タップ → 許可 → 反映 |

| 明細突き合わせ | キャリアの請求明細と積算値・金額を比較し、設定値を調整 |

### 12.1 除外番号の分類細分化（検討事項、実装未着手）

現在の除外リストは 1 本の `List<String>`（5.3.2）で一律に集計対象外としている。これを次の 2 分類に分ける案。

| 分類 | 対象例 | 扱い |
|---|---|---|
| 無料通話 | 110 / 119 / 104 / 0120 等 | 金額計算不要。現状の除外と同じ |
| 要追跡 | 0570 / 0180 / 0990 / 国際電話等 | 可能なら番号ごとに専用の単価（`unitSec` / `unitPrice`）を任意設定でき、単価があれば金額を計算、なければ「課金 ¥不明」と表示する |

要追跡分の集計は、メインの定額枠計算（`Result` / `calculate()`）には合算せず、完全に別枠のセクション（例:「その他の課金」）として表示する方針。

影響範囲は `Billing.kt`（データ構造・`isExcluded`）、`AppSettings.kt`（テキスト⇔構造化データの変換）、`SettingsRepository.kt`（保存形式）、`SettingsScreen.kt`（UI）、`MainActivity.kt`（別枠集計の表示）に及び、Phase 1 つ分相当の作業量が見込まれる。
