パッケージ名:io.github.eightbrows.CallTimeChecker

通話時間・通話料金積算ウィジェット

| 項目 | 内容 |
|---|---|
| ドキュメント版数 | 0.1 |
| 作成日 | 2026-08-18 |
| 状態 | 検討中 |

---

## 1. 概要

契約中の音声通話プランについて、当月の積算通話時間と概算通話料金をホーム画面ウィジェットに常時表示する Android アプリケーション。

端末の通話履歴 (`CallLog`) を定期的に取得してローカル DB に蓄積し、契約プランの設定値に基づいて集計・課金計算を行う。

### 1.1 解決したい課題

- 定額枠（月間 70 分等）をどれだけ消費したかがキャリアアプリを開かないと分からない
- キャリアアプリは起動が重く、反映も遅い
- ホーム画面で残量を一目で把握したい

### 1.2 設計方針

| 方針 | 理由 |
|---|---|
| 生ログをそのまま保存し、判定・課金計算は集計時に実施 | 設定変更時に過去分も再計算され、キャリア明細と突き合わせて設定を追い込める |
| 集計ロジックを純粋関数として分離 | 実機なしで JVM ローカルテストが可能 |
| 表示は常にローカル DB を参照 | 端末の `CallLog` が削除されても影響を受けない |
| プラン形式を 2 パラメータに抽象化 | 月間定額型・1 通話定額型・併用型を分岐なしで扱える |
| 外部ライブラリ・ネットワーク通信なし | 権限の追加要求が不要、保守が容易 |

## 2. スコープ

### 2.1 対象

- 標準の電話アプリによる音声発信の積算
- 契約起算日に基づく期間集計
- 定額枠消費量および超過料金の算出
- ウィジェットへの表示（30 分自動更新・タップ手動更新）

### 2.2 対象外

- 着信通話の積算（日本の一般的なプランでは課金対象外のため）
- IP 電話 / VoIP アプリ（Google Meet 等）の通話。`CallLog` に記録されないため原理的に取得不可
- データ通信量の集計
- キャリアの請求システムとの連携・照合
- 複数 SIM の個別集計（シングル SIM 運用前提）
- Google Play への公開（`READ_CALL_LOG` は Play 側で用途審査対象。GitHub Releases での自己配布を想定）

## 5. 機能要件

### 5.1 通話記録の取得

#### 5.1.1 取得元

`android.provider.CallLog.Calls` コンテンツプロバイダ。

| 列 | 用途 |
|---|---|
| `DATE` | 通話開始時刻（epoch millis）。主キーとして使用 |
| `DURATION` | 通話接続時間（秒）。未応答は 0 |
| `NUMBER` | 相手先番号。除外判定に使用 |
| `TYPE` | 通話種別。`OUTGOING_TYPE`(2) のみ対象 |
| `PHONE_ACCOUNT_ID` | 発信元アカウント。IP 電話混入時の切り分け用 |

#### 5.1.2 同期処理

```
1. last = SELECT MAX(date_millis) FROM call_record   (レコードなしの場合は 0)
2. CallLog を以下の条件で問い合わせ
     TYPE = 2 AND DATE >= (last - 86400000)
   ※ 24 時間分の重複読み込みにより、ログ書き込み順序の揺らぎを吸収する
3. 取得したレコードを INSERT OR IGNORE で投入
```

- 主キー重複により冪等性が担保される。何度実行しても結果は変わらない
- 差分のみを対象とするため、30 分間隔での実行でも負荷は無視できる
- 初回実行時のみ `CallLog` 全件を読み込む

#### 5.1.3 実行タイミング

| 契機 | 備考 |
|---|---|
| ウィジェット自動更新（30 分周期） | `updatePeriodMillis` による |
| ウィジェットタップ | 手動更新 |
| アプリ本体の起動時 | |
| 設定変更後 | 同期は不要だが再集計・再描画を行う |

### 5.2 集計期間の決定

起算日 `startDay`（1〜31）に対し、集計期間は `[開始日 00:00:00.000, 翌月開始日 00:00:00.000)` の半開区間とする。

タイムゾーンは端末のデフォルトを使用する。

```kotlin
/** 指定月における期間開始日。存在しない日は月末にクランプする */
fun periodStartDate(startDay: Int, ym: YearMonth): LocalDate =
    ym.atDay(minOf(startDay, ym.lengthOfMonth()))

/** today が属する集計期間の「開始月」 */
fun periodMonth(startDay: Int, today: LocalDate): YearMonth {
    val ym = YearMonth.from(today)
    return if (!today.isBefore(periodStartDate(startDay, ym))) ym else ym.minusMonths(1)
}

/** 開始月を指定した集計期間 */
fun periodOf(startDay: Int, zone: ZoneId, month: YearMonth): Pair<Long, Long> {
    val start = periodStartDate(startDay, month)
    val end = periodStartDate(startDay, month.plusMonths(1))
    return start.atStartOfDay(zone).toInstant().toEpochMilli() to
           end.atStartOfDay(zone).toInstant().toEpochMilli()
}

fun currentPeriod(startDay: Int, zone: ZoneId, today: LocalDate): Pair<Long, Long> =
    periodOf(startDay, zone, periodMonth(startDay, today))
```

集計期間は開始月（`YearMonth`）と 1 対 1 に対応する（`periodStartDate()` が開始月から開始日を一意に決めるため）。月送り（5.6）はこの性質を使い、開始月を `YearMonth` 単位でずらして表す。

基準日そのものを `LocalDate.plusMonths()` でずらす方式は採らない。`LocalDate` 側の日クランプと `periodStartDate()` の月末クランプが二重にかかり、起算日が月末にクランプされる月で前月が今月と同じ期間になるため。例えば起算日 31・基準日 2026/3/30 のとき、今月は 2/28-3/31 だが、基準日を 1 ヶ月戻すと 2026/2/28 となり同じ 2/28-3/31 に着地してしまう。開始月を戻せば 2026-02 → 2026-01 となり、正しく 1/31-2/28 が得られる。

#### 5.2.1 仕様上の決定事項

| 論点 | 決定 |
|---|---|
| 起算日 25 の場合の範囲 | 25 日 00:00 〜 翌月 24 日 23:59:59.999 |
| 起算日 31、2 月の扱い | 2 月 28 日（閏年は 29 日）にクランプ |
| 期間をまたぐ通話 | 通話**開始時刻**が属する期間に計上する |
| 設定可能範囲 | 1〜31 |

### 5.3 除外判定

#### 5.3.1 判定手順

1. 番号文字列からハイフン、スペース、括弧を除去する
2. 除外リストの各エントリと前方一致比較を行う
3. いずれかに一致した場合、その通話は定額枠を消費せず、課金計算の対象外とする
4. 除外された通話は「除外通話時間」として別枠で集計・表示する

番号が空文字列または `null`（非通知等）の場合は除外扱いとしない。

#### 5.3.2 除外リスト初期値

| プレフィックス | 内容 |
|---|---|
| `0570` | ナビダイヤル |
| `0180` | テレドーム |
| `0990` | ダイヤルQ2 |
| `0120` | フリーダイヤル |
| `104` | 番号案内 |
| `110` | 警察 |
| `118` | 海上保安庁 |
| `119` | 消防・救急 |
| `188` | 消費者ホットライン |
| `+` | 国際発信 |

設定画面で編集可能とする（改行区切りのテキストとして保持）。

### 5.4 料金計算

#### 5.4.1 パラメータ

| 変数 | 意味 | 単位 |
|---|---|---|
| `monthlyFreeSec` | 月間定額枠 | 秒 |
| `perCallFreeSec` | 1 通話あたり無料時間 | 秒 |
| `unitSec` | 課金単位 | 秒（30 または 60） |
| `unitPrice` | 単位あたり金額 | 円 |

#### 5.4.2 プラン形式との対応

| プラン形式 | `monthlyFreeSec` | `perCallFreeSec` | 例 |
|---|---|---|---|
| 月間定額型 | 定額枠の秒数（1 分以上） | 0 | 月 70 分 + 22 円/30 秒 |
| 1 通話定額型 | 0 | 無料時間の秒数（1 分以上） | 5 分かけ放題 + 22 円/30 秒 |
| 従量課金 | 0 | 0 | 22 円/30 秒 |

3 択のいずれも「一方だけが正」または「両方 0」であり、プラン形式と 2 フィールドの組み合わせは 1 対 1 に対応する。したがってプラン形式は保存値から一意に導出でき（`derivePlanType()`）、読み込み時はこの導出結果を採用する（5.7 のマイグレーション）。

集計ロジック（`calculate()`）は両方が正の値であっても動作する（1 通話ごとの無料分を引いた残りを月間枠から消費する）が、設定画面から作れる組み合わせではないため、プラン形式としては用意しない。旧バージョンに存在した「併用型（カスタム）」はこの理由で廃止した。

#### 5.4.3 アルゴリズム

```kotlin
data class Settings(
    val monthlyFreeSec: Int,
    val perCallFreeSec: Int,
    val unitSec: Int,
    val unitPrice: Int,
    val excludePrefixes: List<String>
)

data class Result(
    val countedSec: Int,       // 定額対象として計上した通話の実時間合計
    val quotaConsumedSec: Int, // 実際の定額枠消費量（通話ごとに単位切り上げした値の合計）
    val billedSec: Int,        // 課金対象秒数（単位切り上げ済み）
    val amount: Int,           // 概算料金（円）
    val excludedSec: Int,      // 除外番号への通話の実時間合計
    val callCount: Int,        // 対象通話件数
    val billedCallCount: Int   // 課金が発生した通話件数
)

fun calculate(records: List<CallRecord>, s: Settings): Result {
    var pool = s.monthlyFreeSec
    var countedSec = 0
    var quotaConsumedSec = 0
    var billedSec = 0
    var excludedSec = 0
    var callCount = 0
    var billedCallCount = 0

    for (r in records.sortedBy { it.dateMillis }) {
        if (isExcluded(r.number, s.excludePrefixes)) {
            excludedSec += r.durationSec
            continue
        }
        if (r.durationSec == 0) continue   // 未応答

        countedSec += r.durationSec
        callCount++

        val over = maxOf(0, r.durationSec - s.perCallFreeSec)
        if (over == 0) continue

        // 通話ごとに課金単位へ切り上げる
        val units = ceilDiv(over, s.unitSec) * s.unitSec
        // 枠が尽きた後も、消費量そのものは切り上げ値の合計として積み上げる
        quotaConsumedSec += units
        val consumed = minOf(units, pool)
        pool -= consumed
        val billed = units - consumed
        if (billed > 0) {
            billedSec += billed
            billedCallCount++
        }
    }
    return Result(
        countedSec = countedSec,
        quotaConsumedSec = quotaConsumedSec,
        billedSec = billedSec,
        amount = billedSec / s.unitSec * s.unitPrice,
        excludedSec = excludedSec,
        callCount = callCount,
        billedCallCount = billedCallCount
    )
}

fun ceilDiv(a: Int, b: Int): Int = (a + b - 1) / b
```

`countedSec` と `quotaConsumedSec` は用途が異なる。

| フィールド | 意味 | 主な用途 |
|---|---|---|
| `countedSec` | 通話の実時間合計（切り上げなし） | 実際に何分話したかの参考表示 |
| `quotaConsumedSec` | 通話ごとに課金単位へ切り上げた値の合計 | 全プランの「通話時間」表示・定額枠の使用率による配色判定 |

短い通話が多いほど両者は乖離する（例: 2 秒の通話 39 件は `countedSec = 78` 秒だが、30 秒単位では `quotaConsumedSec = 1170` 秒）。定額枠を実際に減らすのも料金の根拠になるのも後者のため、5.5.1 / 5.6.1 の「通話時間」表示には `quotaConsumedSec` を使う（`countedSec` は「履歴集計」の実時間表示のみ）。

#### 5.4.4 計算上の決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 切り上げの単位 | 通話ごとに切り上げ | キャリアの課金方式に最も近い |
| 定額枠の消費量 | 切り上げ**後**の秒数（`quotaConsumedSec`） | 同上 |
| 枠が尽きた後の消費量 | 切り上げ値の合計を積み上げ続ける | 枠に対して何分超過したかを表示するため |
| 通話の処理順 | 通話開始時刻の昇順 | 定額枠の消費順序を実際の時系列に一致させる |
| 通話時間 0 秒 | 集計対象外 | 未応答・不通のため |
| 除外番号への通話 | 定額枠を消費せず、料金も計上しない | 別建て課金のため本アプリでは追跡しない |

### 5.5 ウィジェット

#### 5.5.1 表示内容

サイズは 2×2 を推奨（2×1 では窮屈になるため）。

「ラベル（小）+ 値（大）」のブロックを 2 つ縦に並べる。アプリ本体の「現在の状況」（5.6.1）と同じ構成・同じ数字にして、両者を見比べたときに食い違わないようにする。

```
通話時間 / 無料枠残     ← ラベル
20.5 / 49.5分          ← 値
通話金額               ← ラベル
0円                    ← 値
```

ラベルと値はプラン形式ごとに変わる。分表示は分単位・小数第一位（`formatMinutes()`、5.6.1 と共用）。

| プラン形式 | ブロック1のラベル | ブロック1の値 |
|---|---|---|
| 月間定額型 | `通話時間 / 無料枠残` | `20.5 / 49.5分`（`quotaConsumedSec` と残り枠） |
| 1 通話定額型 | `通話時間` | `128.0分`（`quotaConsumedSec`） |
| 従量課金 | `通話時間` | `42.0分`（`quotaConsumedSec`） |

ブロック2は全プラン共通で `通話金額` / `220円`（`Result.amount`）。

通話時間は全プランとも `Result.quotaConsumedSec`（通話ごとに課金単位へ切り上げた合計、5.4.3）を用いる。月間定額型の残り枠・配色判定も同じ値を分子とする。実通話時間（`countedSec`）ではないため、短い通話が多い月は実際に話した時間より大きい値が表示されるが、これは「通話時間」の表示値が「通話金額」の計算根拠と一致していることを優先した意図的な仕様（下記）。

超過の有無は文字ではなく背景色（5.5.3）だけで表す。対象通話件数はウィジェットには出さず、アプリ本体の「履歴集計」（5.6.1 / 5.6.2）で確認する。1x2 の最小サイズに収めるための割り切りで、件数はウィジェットで常時見る必要がないため。

文字サイズはラベルを 11sp、値を 18sp とし、桁数が増えた場合に切れないよう値は 12sp、ラベルは 9sp まで autoSize で自動縮小する。以前の 4 行構成では 17sp が 1x2 最小サイズの上限だったが、2 ブロック構成でラベルが小さくなった分の余裕を値に回している（最長ケース `20.5 / 1419.5分` で切れないことを実機確認済み）。

#### 5.5.2 表示状態

| 状態 | 表示 | 遷移先 |
|---|---|---|
| `NORMAL` | 上記の通常表示 | タップで手動更新 |
| `NO_PERMISSION` | 「タップして権限を許可」 | タップでアプリ本体を起動 |
| `ERROR` | 「更新失敗」 | タップで再試行 |

#### 5.5.3 配色

| 条件 | 色 |
|---|---|
| 残り時間が警告しきい値より多い | 通常色 |
| 残り時間が警告しきい値以下、かつ枠消費量が定額枠未満 | 警告色 |
| 枠消費量が定額枠以上 | 超過色 |

残り時間は `定額枠 − Result.quotaConsumedSec`（枠消費量は 5.4.4）。警告色に切り替わる位置は設定項目「警告しきい値（残り分）」（5.7）で決まり、初期値は定額枠の 20%（定額枠 70 分なら残り 14 分 = 消費 56 分）で、しきい値が設定項目になる前の「使用率 80% で警告」と同じ位置になる。消費量ではなく残り時間で持つのは、「あと何分使えるか」が利用者の関心そのものであり、定額枠が変わっても「残り 10 分で警告」という設定の意味が変わらないため。超過色に切り替わる位置は定額枠そのもので固定とする（「使い切った」以外の意味を持たせようがないため）。しきい値が 1〜(定額枠 − 1) の範囲外のとき（定額枠 1 分など）は警告色の帯が存在せず、通常色から直接超過色に切り替わる。定額枠 0 分は設定画面から作れない（5.7 のマイグレーション）が、消費 0 秒が超過扱いにならないよう定額枠が正のときだけ超過判定を行う。

1 通話定額型・従量課金には月間の定額枠が無く、残り時間そのものが定義できないため「警告しきい値（残り分）」は使わない（設定欄もグレーアウトする）。1 通話定額型では使用率が定義できないため、課金額 0 円かどうかで通常色／警告色を切り替える（超過色は使わない）。従量課金は無料枠が無く「超過」という概念自体が無いため、金額が出ていても常に通常色とする。

背景は固定の色リソース（`setBackgroundResource`）ではなく、透過率（5.7）を反映した ARGB を `setBackgroundColor` で設定する。3 色の実体は設定で選ばれたプリセットパレットの色（`WIDGET_COLOR_PALETTE`、5.7）で、いずれも不透明のまま持ち `withAlpha()` で alpha チャンネルだけを差し替える（段階 → alpha の換算は `widgetBgAlpha()`、0 段階目 = 255、8 段階目 = 0）。透過率は上表 3 色すべてに加え、権限要求 / 更新中 / 更新失敗の各状態（5.5.2）にも同じ値を適用する。これらの状態は権限要求・更新中が通常色、更新失敗が超過色を使うため、カスタム色もそのまま反映される。

文字色は背景色から自動で決める（`widgetTextColorOn()`）。背景の相対輝度（WCAG 2.x の定義）を求め、黒文字と白文字のコントラスト比が高い方を選ぶ。背景色を利用者が選べる以上、「通常色 = 黒文字 / 警告色・超過色 = 白文字」という固定の対応では読めない組み合わせ（通常色にダークグレー、超過色にホワイトなど）が作れてしまうため。この規則により、初期値の警告色（橙 `#FFA000`）の文字色は従来の白から黒に変わる（コントラスト比 2.05 → 10.3）。パレットの全色が黒／白いずれかで 4.5 以上のコントラスト比を満たすことはユニットテストで担保する。

alpha は文字色の判定に使わない（不透明色として判定する）。透過後の見え方は壁紙次第で決まらないため。透過率を上げるほど壁紙の明暗によっては文字が読みにくくなるが、透過率は利用者が明示的に選ぶ設定であり、読みやすさとのトレードオフは利用者に委ねる。透過率 100% では背景色そのものが見えなくなるが、これも仕様として許容する。

### 5.6 アプリ本体

単一 Activity 構成。メイン画面は「サマリ」「通話履歴」の 2 タブ（`TabRow` + `HorizontalPager`）で構成する。

| 領域 | 内容 |
|---|---|
| ヘッダ | アプリ名「通話時間確認アプリ」と、手動更新・設定のボタン。タブの外に置く |
| 月送り | 横 1 行。左に相対ラベル（今月 / 1ヶ月前…）、右に「← 前月」「次月 →」。ヘッダとタブの間、タブの外に置く |
| サマリタブ | 上段（プラン情報）+ 中段「現在の状況」。5.6.1 |
| 通話履歴タブ | 「履歴集計」+ 通話履歴（内訳リスト）。5.6.2 |
| 権限 | 未許可時に要求ボタンを表示 |

手動更新・設定のボタンをヘッダに置くのは、どちらのタブからも操作できる必要があるため。タブの中に置くと、通話履歴タブで内訳リストと一緒にスクロールしてしまううえ、リストに使える縦幅も削ってしまう。アプリ名もヘッダに置くことで、両タブ共通の見出しになり、1 行で済む。

ボタンは `FilledTonalButton` とし、高さ 48dp（Material のタップターゲット推奨最小）・水平パディング 16dp・文字 `titleMedium`（16sp）とし、タップ領域を約 69x51dp（従来比およそ 1.5 倍の面積）とする。`TextButton` の既定サイズ（約 58x40dp・14sp）では押しづらく、背景色が無いためボタンだと気付きにくいため。ボタン 2 つで幅を使う分、アプリ名は `TextOverflow.Ellipsis` で省略して折り返さないようにする。水平パディングを 20dp ではなく 16dp としたのは、20dp だと 411dp 幅・`font_scale` 1.15 の実機でアプリ名が省略されてしまったため。

月送りは表示する期間を過去方向へさかのぼるためのもの。両タブの表示期間を同時に切り替えるため、ヘッダと同じくタブの外（ヘッダ行とタブの間）に置き、どちらのタブを見ていても同じ位置で操作できるようにする。ボタンはヘッダの更新・設定と同じ `FilledTonalButton`（高さ 48dp）とし、押せることを背景色で示す。相対ラベルはボタンではないためテキストのままとし、行の左側に置く。ボタン 2 つは右端に寄せて 8dp 間隔で隣り合わせる（ラベル側に `weight(1f)` を持たせる）。両端に振り分けると前月と次月を続けて押すたびに画面幅を横断することになるため（実機で中心間 288dp）、指の移動量を減らす方（同 99dp）を優先する。上に 12dp・下に 16dp の余白を置き、すぐ上のヘッダボタンやすぐ下のタブを誤タップしないようにする（下を厚くしているのは、タブが横幅いっぱいのタップ領域を持つため）。

選択中の月は `monthOffset`（0 = 今月、-1 = 前月…）として画面の状態としてのみ保持し、アプリを終了して開き直すと今月に戻る。過去方向に制限は設けない（記録が無ければ 0 件の結果になるだけ）が、「次月」は今月より先へ進めないよう `monthOffset = 0` のとき無効にする。ラベルを「2026年9月」のような絶対表記にしないのは、起算日が 1 日でない場合（例: 8/25-9/24）にどちらの月を指すのか解釈が割れるため。正確な日付はサマリタブの「期間:」行で確認できる。

設定（定額枠・単価など）は過去の月を選んでいる場合も常に現在の値を使う。設定の変更履歴は保持しない。通話履歴タブ（5.6.2）の内訳リストも同じ期間で絞り込まれる（同一のクエリ結果を使うため自動的に追従する）。ウィジェットは常に今月を表示する（`currentPeriod()` を使い続ける）。

タブはタップに加えて左右スワイプでも切り替えられるようにする。`rememberPagerState` を `LoadedContent` の外（更新のたびに `UiState.Loading` を挟むため）で保持し、`TabRow` の `selectedTabIndex` とタブのタップ（`animateScrollToPage`）を同じ `PagerState` に紐付ける。インジケーターはスワイプ中も指に追従させたいので、`TabRowDefaults.SecondaryIndicator` の位置と幅を `currentPage + currentPageOffsetFraction` で隣のタブとの間を補間して決める（既定のインジケーターは選択確定後にアニメーションするだけで、スワイプ量には追従しない）。`TabRow` は `PrimaryTabRow` / `SecondaryTabRow` に置き換え予定の deprecated API だが、補間に必要な `List<TabPosition>` を `indicator` に渡してくれるのは現状この API のみのため、こちらを使う。

縦スクロール（内訳リスト）と横スワイプ（ページ送り）の振り分けは Compose の入れ子スクロールに任せる。実機で確認した挙動は次のとおり。

| 操作 | 結果 |
|---|---|
| 内訳リスト上での斜めドラッグ（縦優勢、40 度程度まで） | リストが縦スクロールし、タブは切り替わらない |
| 内訳リスト上でのほぼ水平なドラッグ | タブが切り替わる |
| 「履歴集計」やフィルタ行など、リスト外から始まる斜めドラッグ | タブが切り替わる（その場所に縦スクロールする対象が無いため） |

#### 5.6.1 サマリタブ

| 段 | 内容 |
|---|---|
| 上段 | 通常サイズで縦に並べる: `プラン: 月間定額型`、`期間: 2026/08/01 - 2026/08/31`、`無料枠: 70分`（月間定額型のみ）または `1通話無料枠: 5分`（1 通話定額型のみ）、`単価: 30秒 / 22円`（全プラン共通） |
| 中段 | 見出し「現在の状況」。項目ごとに、小さめフォントのラベル行と大きめフォントの値行をペアで縦に並べる |
| 下段 | 見出し「履歴集計」。内容は通話履歴タブ（5.6.2）と同じものを再掲する |

「履歴集計」を両タブに出すのは、通話履歴タブに切り替えなくても件数と実時間が分かるようにするため。同じ composable（`HistorySummary`）を両方から呼ぶ。

中段の項目はプラン形式ごとに変わる。

| プラン形式 | ラベル | 値 | バッジ |
|---|---|---|---|
| 月間定額型 | `通話時間 / 無料枠残` | `20.5 / 49.5分`（`quotaConsumedSec` と残り枠） | `quotaConsumedSec > monthlyFreeSec` なら `超過あり`（danger 色）、そうでなければ `超過なし` |
| 1 通話定額型 | `通話時間` | `128.0分`（`quotaConsumedSec`） | `billedCallCount > 0` なら `超過あり`、そうでなければ `超過なし` |
| 従量課金 | `通話時間` | `42.0分`（`quotaConsumedSec`） | なし（無料枠が無く「超過」が定義できないため） |
| 全プラン共通 | `通話金額` | `220円`（`amount`） | なし |

通話時間の基準は、ウィジェット（5.5.1）と数字が食い違わないよう同じ基準で選ぶ。全プランとも `Result.quotaConsumedSec` とする。プランごとに基準を変えないのは、「通話時間」の表示値は「通話金額」の計算根拠（`quotaConsumedSec ÷ unitSec × unitPrice`）と一致しているべき、という原則を優先するため。月間定額型以外（`monthlyFreeSec = 0`）では `quotaConsumedSec` と `billedSec` が常に一致するので、表示値から金額をそのまま逆算できる。実際に何分話したかは「履歴集計」に「通話時間（実時間）」として `countedSec` を併記する。

分表示は分単位・小数第一位（`20.5分`）とし、`formatMinutes()` をウィジェットと共用する。「履歴集計」の「通話時間（実時間）／（除外）」は生ログの確認用のため分秒表示とする。

表示の分岐は `monthlyFreeSec > 0` のような値の判定ではなく `PlanType` で行う（5.4.2 のとおり両者は 1 対 1 に対応するため結果は同じだが、プラン形式ごとに項目が変わる以上こちらの方が意図が明確）。

#### 5.6.2 通話履歴タブ

| 領域 | 内容 |
|---|---|
| 履歴集計 | `通話件数: 41件（課金対象 5件）`、`通話時間（実時間）: 1分35秒`、`通話時間（除外）: 0分0秒` |
| 通話履歴 | 期間内の通話一覧。日時、番号、通話時間、判定結果（定額内 / 課金 ¥XX / 除外 / 未応答）、課金枠の秒数。「全件 / 課金対象のみ」の表示フィルタ切り替え可 |

内訳リストは、キャリアの請求明細と突き合わせて端数処理・除外ルールの妥当性を検証する唯一の手段であるため、初期リリースに含める。画面の縦幅を最大限使えるよう、通話履歴タブの残り領域をすべて内訳リストに割り当てる。

各行の判定結果は「実際に料金が発生したか」を表すため `CallDetail.billedSec` 基準のままとする。加えて、サマリの通話時間と突き合わせられるよう、枠を消費した通話には `CallDetail.quotaConsumedSec`（切り上げ後の秒数）を `定額内・課金枠 30秒` の形式で併記する。

### 5.7 設定項目

| 項目 | 型 | 範囲 | 初期値 | 備考 |
|---|---|---|---|---|
| プラン形式 | 選択 | — | 月間定額型 | 月間定額型 / 1 通話定額型 / 従量課金 |
| 起算日 | 分 | 1〜31 | 1 | 契約開始日 |
| 定額枠 | 分 | 1〜1440 | 70 | 入力できるのは月間定額型のときのみ。それ以外は 0 固定 |
| 通話別無料時間 | 分 | 1〜180 | 5 | 入力できるのは 1 通話定額型のときのみ。それ以外は 0 固定 |
| 課金単位 | 30 / 60 | — | 30 | 秒 |
| 単位金額 | 円 | 0〜999 | 22 | |
| 除外番号リスト | テキスト | — | 5.3.2 の初期値 | 改行区切り |
| 警告しきい値（残り分） | 分 | 1〜(定額枠 − 1) | 定額枠の 20%（初期値では 14） | 残りがこの分数以下で警告色。入力できるのは月間定額型のときのみ（5.5.3） |
| ウィジェット背景の透過率 | 段階 | 0〜8 | 0（不透明） | 0%〜100% を 12.5% 刻みの 9 段階（5.5.3） |
| ウィジェット背景色（通常色 / 警告色 / 超過色） | 添字 | 0〜7 | ホワイト / オレンジ / レッド | 8 色のプリセットパレットから選ぶ（5.5.3） |

定額枠と通話別無料時間の下限が 0 ではなく 1 なのは、0 なら従量課金そのものであり、プラン形式の選択と値が食い違った状態（「月間定額型なのに枠が 0 分」）を作らせないため。0 固定側の欄は検証対象外とする（`monthlyFreeMinRange()` / `perCallFreeMinRange()` が `null` を返し、`validateRange()` が検証をスキップする）。プラン形式を切り替えて 0 固定だった欄が有効になったとき、その値が 0 のままなら初期値（70 分 / 5 分）を自動投入する。切り替えた直後にいきなりエラー表示になるのを避けるため。

範囲チェックは入力のたびに `validateRange()` で評価し、範囲外・空欄の欄はエラー表示にしたうえで**保存ボタンを無効化**する。入力そのものは制限しない（`1440` を `70` に直す途中の中間状態を壊さないため）。数値欄は数字以外の文字だけを入力時に取り除く。`clamp*` / `normalizeUnitSec` は保存時の保険として残す（保存に到達する時点で値は範囲内）。`clampMonthlyFreeMin` / `clampPerCallFreeMin` の下限が 0 のままなのは、0 固定のプラン形式で保存される値が 0 だから。

**マイグレーション**: 読み込み時は保存済みの `plan_type` を信用せず、定額枠・通話別無料時間の実値から `derivePlanType()` で導出し直す（`migrateAppSettings()`）。これにより、廃止した「カスタム」が保存されている場合の読み替え（両方 > 0 なら月間定額型を優先し、通話別無料時間は 0 に切り捨てる）と、プラン形式と値が矛盾している場合の解消（月間定額型 + 定額枠 0 分 → 従量課金）の両方を 1 つの規則で賄える。導出結果は必ず上表の範囲を満たすため、読み込み直後に保存不可の状態になることはない。`plan_type` の書き込み自体は、保存内容を外から読んだときに分かりやすいよう残している。

プラン形式は UI 上のプリセットに過ぎず、内部的には `monthlyFreeSec` と `perCallFreeSec` の 2 フィールドに書き込むのみ。集計ロジックはプラン形式を参照しない。現在のプラン形式は、設定画面ではプラン形式のラジオボタン自体が表示を兼ねる。アプリ本体（5.6）では集計期間の行に併記する（プラン形式によってサマリの分子の基準と分母の有無が変わるため）。

ウィジェット背景の透過率は、0.125 刻みの実数ではなく段階インデックス（0〜8）で保持・保存する。保存値を整数にすることで、`alpha` への換算時の端数処理を `widgetBgAlpha()` 1 箇所に閉じ込められるため。UI はプルダウン（`ExposedDropdownMenuBox`）とし、閉じている状態でも現在値（`0%` / `12.5%` / … / `100%`）を文字で読めるようにする。ラジオ 9 個は横幅に収まらず、数値入力にすると 12.5% 刻みという制約を利用者に押し付けることになるため。配置は除外番号リストの下・ウィジェット背景色の上とし、ウィジェットの見た目に関する設定をまとめる。縦幅を詰めるため、項目名を左・プルダウンを右に横 1 行で並べる（プルダウンは `100%` と展開アイコンが収まる 140dp 固定幅、項目名は残り幅）。

この位置ではアンカーが画面中ほどに来るため、プルダウンは上方向に展開し、9 項目すべては一度に収まらない（項目の高さは `DropdownMenuItem` の最小高 48dp で決まる）。そのため `ExposedDropdownMenu` に `scrollState` を渡し、開いたときに選択中の項目が中央に来る位置までスクロールしておく。選択中が `100%` でもスクロール操作なしにその項目が見える。

メニューの高さは展開直後には確定しておらず `maxValue` / `viewportSize` がまだ 0 のため、`snapshotFlow { maxValue }.first { it > 0 }` で確定を待ってから `scrollTo()` する。全項目が収まる場合は `maxValue` が 0 のままこの待機が完了しないが、スクロール自体が不要であり、メニューを閉じた時点で `LaunchedEffect` ごとキャンセルされるので問題にならない。

警告しきい値は割合（%）ではなく「残り何分か」という分数で保持する。割合で持つと定額枠を変えたときにしきい値の分数が勝手に動いてしまい、消費量で持つと定額枠を変えたときに「あと何分で警告が出るか」が変わってしまうため。残量で持てば、定額枠が何分であっても「残り 10 分になったら警告」という設定の意味は変わらない。設定画面では入力欄の右に `warnRemainingLabel()` で `残り14分` と表示し、入力した数字が消費量ではなく残量であることを取り違えないようにする。割合（%）は併記しない。

上限を「定額枠 − 1」とするのは、残りが定額枠と同じ値だと消費 0 分の時点で既に警告色になってしまい、警告として意味を持たないため。定額枠を後から警告しきい値以下に変更した場合は、しきい値の欄をエラー表示にして保存ボタンを無効化する（他の数値欄と同じ方針）。自動でクランプはしない。利用者が明示的に変えていないしきい値が黙って書き換わるのを避けるため。読み込み時のマイグレーション（`migrateAppSettings()`）だけは、外部から書き換えられた保存値で設定画面が開いた直後に保存不可にならないよう、範囲外なら既定値（残り 20%）に戻す。プラン形式を月間定額型に切り替えたときも同様に、範囲外の場合だけ既定値を入れ直す。範囲を持たないプラン形式（1 通話定額型・従量課金）では値をそのまま保持する。月間定額型に戻したときに元の設定を復元できるようにするため。

保存キーは残量ベースの `warn_remaining_min`。開発途中に消費量ベースで保存していた旧キー（`warn_threshold_min`）が残っている場合は、切り替わるタイミングが変わらないよう `定額枠 − 消費しきい値` として読み替える（定額枠 50 分・消費しきい値 20 分なら残り 30 分）。読み替えた旧キーは次の保存時に削除する。保存内容を外から読んだときに、意味の違う値が 2 つ並ぶのを避けるため。

警告しきい値の UI は、直接入力できる数値欄に +/- ボタン（±1 分）を添えた形とする。刻みが 1 分と細かいので、大きく動かすときは直接入力、微調整はボタンという使い分けができる。ボタンは範囲の端で無効化する。

ウィジェット背景色は 3 つの役割（通常色 / 警告色 / 超過色）それぞれについて、8 色のプリセットパレットから選ぶ。保存するのは ARGB ではなくパレットの添字とし、色の実体は `WIDGET_COLOR_PALETTE` 1 箇所に閉じ込める（透過率を段階インデックスで持つのと同じ理由）。並び順が保存値の意味そのものになるため、既存の色の順番は変えず追加は末尾のみとする。任意色のカラーピッカーにしないのは、文字が読めない配色や 3 状態が見分けられない配色を作れてしまうため。UI は役割ごとに 8 個の色見本を等幅（`weight(1f)`）で横 1 行に並べ、選択中は枠を太くしたうえでチェックを重ねる。チェックの色も `widgetTextColorOn()` で決めるので、どの色見本の上でも読める。透過率は 3 色共通のままとし、色ごとの個別設定は持たない。

除外番号リストは常時 4 行分の高さを占めないよう折りたたみ式とする。閉じている状態では `除外番号リスト（10件）` の見出しと、先頭 3 件＋残り件数のプレビュー（`0570, 0180, 0990 ほか7件`）のみを 1 行で表示し、見出しのタップで入力欄と「初期値に戻す」ボタンを展開する。

`READ_CALL_LOG` の許可状態（8 章）も設定画面に表示する。未許可ならその場で権限要求ダイアログを出せるようにし、許可済みの場合も OS のアプリ権限設定への導線（`ACTION_APPLICATION_DETAILS_SETTINGS`）を残す。誤って権限を取り消した場合の復旧経路とするため。OS の権限設定から戻った際は `ON_RESUME` で許可状態を再取得する。日常的に触る設定ではないため、配置は画面下部（バージョン情報の直上）とする。

見出し「設定」と「キャンセル」「保存」ボタンは画面上部に固定し、入力項目のスクロール領域とは分ける。設定項目が縦に長く、以前は画面末尾まで送らないと保存・取り消しができなかったため。「保存」は主操作なので塗りボタン（`Button`）、「キャンセル」は副操作なので枠線ボタン（`OutlinedButton`）とする。両者を同じ見た目にすると、押し間違いのコストが非対称（保存の取り消しは再入力が必要）なのに見分けがつかないため。入力エラー中は「保存」が無効になるので、無効状態がはっきり出る塗りボタンを保存側に割り当てる。サイズはアプリ本体のヘッダ（5.6）と同じ 48dp 高・`titleMedium` に揃える。ヘッダとスクロール領域の境目には区切り線を引く。

画面が縦に伸びないよう、プラン形式のラジオは横 1 行、数値入力欄は 2 カラム（`起算日` / `単位金額`、`定額枠` / `通話別無料時間`）、課金単位は見出しと選択肢を同じ行に置く。`定額枠` と `通話別無料時間` を対で並べるのは、プラン形式によって少なくとも一方がグレーアウトするため（従量課金では両方）。従量課金でも欄を隠さずグレーアウトのまま残すのは、プラン形式を切り替えたときにレイアウトが動かないようにするため。

保存先は `SharedPreferences`。

## 6. データ設計

### 6.1 テーブル定義

```sql
CREATE TABLE call_record (
  date_millis  INTEGER NOT NULL PRIMARY KEY,  -- 通話開始時刻
  duration_sec INTEGER NOT NULL,              -- 接続時間（秒）
  number       TEXT,                          -- 相手先番号
  type         INTEGER NOT NULL,              -- CallLog.Calls.TYPE
  account_id   TEXT                           -- PHONE_ACCOUNT_ID
);

CREATE INDEX idx_call_record_date ON call_record(date_millis);
```

### 6.2 設計上の決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 主キー | `date_millis` | `CallLog._ID` は端末側でログが削除・再構築されると再利用される可能性があるため使用しない。通話開始時刻はミリ秒精度で実質的に一意 |
| 保存内容 | 生ログのみ | 除外判定・課金計算の結果は保存しない。設定変更時に過去分を含めて再計算するため |
| 保持期間 | 無期限 | 年間数千件程度であり容量上の問題がない |
| 削除 | 行わない | 過去期間の参照および設定検証のため |
| `account_id` | 保持する | IP 電話の混入が判明した場合の切り分けに使用 |

## 7. 処理フロー

### 7.1 ウィジェット更新

```
onUpdate / onReceive(ACTION_MANUAL_REFRESH)
  ↓ goAsync()
  ↓ [Executor]
  権限チェック
    未許可 → NO_PERMISSION 状態で描画 → finish()
  ↓
  CallLog 同期（5.1.2）
  ↓
  集計期間の算出（5.2）
  ↓
  DB から期間内レコードを取得
  ↓
  calculate()（5.4.3）
  ↓
  RemoteViews 構築・updateAppWidget
  ↓
  PendingResult.finish()
```

### 7.2 設定変更時

同期は行わず、再集計と全ウィジェットの再描画のみを実行する。

| 権限 | 保護レベル | 用途 |
|---|---|---|
| `android.permission.READ_CALL_LOG` | dangerous | 通話履歴の取得 |

## 9. 制約・既知の限界

| 項目 | 内容 | 対応 |
|---|---|---|
| 通話中の反映 | `CallLog` は通話終了後に書き込まれるため、通話中は積算に反映されない | 仕様として許容 |
| IP 電話 | Google Meet 等は `CallLog` に記録されないため取得不可 | 積算不要のため問題なし。混入が判明した場合は `account_id` で切り分け、除外ルールを追加 |
| `CallLog` の保持上限 | 機種により保持件数に上限がある（500 件程度の例あり） | ローカル DB への蓄積により回避 |
| 初回導入時 | 導入以前の通話は `CallLog` に残っている分しか取得できない | 期間途中での導入時は数値が不完全になる旨をアプリ内に表示 |
| 課金計算の精度 | 切り上げ単位・カウント開始タイミングがキャリアにより異なる | 内訳リストで明細と突き合わせ、設定で調整 |
| Doze による遅延 | 自動更新が最大で数十分遅延する場合がある | 手動更新で補完。必要ならバッテリー最適化の除外を案内 |
| 表示金額の位置づけ | あくまで概算。基本料金・ユニバーサルサービス料・消費税等は含まない | アプリ内に注記 |

## 10. テスト方針

### 10.1 ユニットテスト（JVM ローカル）

集計ロジックは `List<CallRecord>` と `Settings` を受けて `Result` を返す純粋関数であり、実機なしで検証可能。以下を優先的にテストする。

| 対象 | ケース |
|---|---|
| 期間算出 | 起算日 1 / 25 / 31、2 月（閏年・平年）、月初日・月末日の境界 |
| 月送り | 開始月の判定（起算日の前日・当日）、開始月指定での期間算出（起算日 25 / 31、閏年）、月末クランプされる月の前月が今月と別期間になること |
| 警告しきい値（残り分） | 既定値（定額枠の 20%）、範囲（1〜定額枠 − 1）、20% が 1 分未満になる定額枠、範囲が空になる定額枠 1 分、マイグレーションでの復旧 |
| ウィジェット配色 | 残り時間がしきい値に達した位置での警告色の切り替わり、しきい値を消費量と取り違えていないこと、超過色が定額枠固定であること、パレットの添字と色の対応、背景色から決まる文字色が全色でコントラスト比 4.5 以上 |
| 切り上げ | 端数 0 秒、1 秒、29 秒、30 秒、31 秒（`unitSec` = 30 / 60 の両方） |
| 定額枠 | 枠未使用、枠内、枠ちょうど、枠をまたぐ 1 通話、枠超過 |
| 通話別無料時間 | 無料時間ちょうど、1 秒超過、大幅超過 |
| 併用型 | `monthlyFreeSec` と `perCallFreeSec` の両方が正の場合 |
| 除外判定 | 各初期値プレフィックス、ハイフン付き番号、空番号、`null` |
| 境界 | 通話時間 0 秒、期間開始時刻ちょうど、期間終了時刻の直前・直後 |

### 10.2 実機確認

| 項目 | 確認内容 |
|---|---|
| 同期の冪等性 | 複数回更新しても件数・積算値が変化しないこと |
| 自動更新 | 30 分周期で更新されること（Doze 下での遅延幅も確認） |
| 権限フロー | 未許可 → ウィジェット表示 → タップ → 許可 → 反映 |

| 明細突き合わせ | キャリアの請求明細と積算値・金額を比較し、設定値を調整 |

### 12.1 除外番号の分類細分化（検討事項、実装未着手）

| 無料通話 | 110 / 119 / 104 / 0120 等 | 金額計算不要。現状の除外と同じ |
